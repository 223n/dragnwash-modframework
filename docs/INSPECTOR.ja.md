# Inspector（設計）

[English](INSPECTOR.md)

> **実験的な機能です。** Tool window ライブラリ（1.1.0）に作り、`main` にありますが、まだリリースには含まれていません。設計と違う点：ベクトル、色、rect、bounds は成分ごとの欄ではなく、カンマ区切りの数値を 1 つの欄に打ちます。マテリアルのテクスチャのプロパティの **Go** は Assets タブを開くだけで、そのテクスチャまでは飛びません。Assets タブの Inspect ボタンはまだありません。

Tool window の **Inspector** タブ。シーンのオブジェクトとそのコンポーネント、それぞれのフィールドとプロパティ、読み込まれているマテリアルのパラメーターを、ゲームを動かしたまま読み、書き換えられるようにします。Unity のエディターの Inspector がやることを、ビルドしかないゲームに対して。Mod を作る人が「これは何で、何という名前で、どんな値を持っているか」を知り、コードを 1 行書く前に変更を試すためのものです。開発者ツールの中の機能（GUIDE のルール 8）で、遊ぶ人が目にすることはありません。

## 何のためで、何ではないか

- **調べる。** 看板の裏にあるオブジェクトの名前、扉を動かすコンポーネント、カウンターのマテリアルとそのシェーダー、洗う速さを持つフィールド。Mod の `GameHooks.Require` や `AssetReplacements` に名前が要るものすべてを、逆コンパイルではなく見て探せます。
- **試す。** 値を変えると、すぐゲームに出ます。保存はしません。変更はシーンの読み直しかゲームの終了までのものです。変更のまとまりを Mod にすることは別の設計です（起動時に Assets ライブラリが当てる上書きファイル。テクスチャの差し替えと同じやり方）。ここでは意図的にやりません。2 つを別々に判断できるようにするためです。
- **RuntimeUnityEditor ではありません。** REPL、引数付きのメソッド呼び出し、コンポーネントの追加と削除、プレハブの生成、ギズモはありません。それらは RuntimeUnityEditor がよくできています。ただしあちらは独自の IMGUI 窓を開き、カーソルと入力を奪うので、Tool window とはぶつかります。FAQ にそう書きます。共存を検証するまでは、どちらか一方で。

## どこに置くか

**Tool window** ライブラリ（Tool window 1.2.0）のタブとして。ゲームからも、ほかのライブラリからも何も要りません。リフレクションと、Unity 自身のシーンとシェーダーの API で足ります。マテリアルの部分は、Assets ライブラリが読み込まれていれば `AssetCatalog` を読みます。今の Assets タブが Tool window を読むのと同じ形（chainloader で確かめる弱い依存で、直接参照しない）です。Assets タブにはマテリアルごとに **Inspect** ボタンが付き、ここに飛びます。

## タブ

左から右に 3 つの区画。狭い窓では、Saves タブの行と同じように、戻るボタン付きの 3 ページになります。

1. **ヒエラルキー。** 読み込まれているすべてのシーン、そのルートのオブジェクトと子を木で。**Search** の入力欄で名前で絞り込み（部分一致、大文字小文字を区別しない）、一致したものをパス付きの平らな一覧にします。非アクティブなオブジェクトは薄い色。木を組むのは、タブを開いたとき、**Refresh** を押したとき、シーンが読み込まれたとき（`GameEvents.OnSceneLoaded`）だけで、毎フレームではありません。シーンには何千ものオブジェクトがあり、`FindObjectsOfType` は安くありません。
2. **コンポーネント。** 選んだオブジェクトのコンポーネントを順に。上にオブジェクトのアクティブ状態、タグ、レイヤー、フルパス。Renderer の **Materials** はコンポーネントのように並ぶので、マテリアルは、それを表示しているオブジェクトから 1 クリックです。コンポーネントを選ぶと 3 つ目の区画に開きます。
3. **メンバー。** コンポーネントのフィールドとプロパティを 1 行ずつ。名前、型、値。public を先に、非公開は **Show private** の切り替えの下に（既定はオフ。非公開フィールド経由で値を入れるのは Mod 作者自身の責任で、ページに一度そう出ます）。値は選んでいるコンポーネントについてだけ Repaint ごとに読むので、ゲームが動けば数字も動きます。毎フレーム変わる値を読むための **Freeze** の切り替えがあります。

## 編集

タブが知っている型の行には操作が付きます。ほかは値を文字で示すだけで、読み取り専用です。

| 型 | 操作 |
|---|---|
| `bool` | トグル |
| `int`、`float`、`double`、`long` などの数値 | 入力欄。Enter で反映。パーサーが受け付けない値は元に戻り、行に理由が出る（Mods 画面の設定ページと同じ規則） |
| `string` | 入力欄 |
| 列挙型 | ボタンで順に切り替え、値が多ければ一覧 |
| `Vector2/3/4`、`Quaternion`（オイラー角で表示）、`Rect`、`Bounds` | 成分ごとの入力欄 |
| `Color` | 4 つの入力欄と色見本 |
| `UnityEngine.Object` の参照（Transform、Material、Texture、別のコンポーネント） | 名前と、それを選ぶ **Go** ボタン。編集不可 |
| 上記のリストと配列 | 展開して要素ごとに 1 行。追加と削除はなし |
| それ以外 | `ToString()`、読み取り専用 |

プロパティは setter があるときだけ編集できます。すべての代入は try/catch の中で行い、ゲームの setter が投げた例外はその行に出て、タブは続きます。`Transform` もほかのコンポーネントと同じ行（`position`、`rotation`、`localScale`）で、特別扱いはしません。

## マテリアルとシェーダー

マテリアル（Renderer から、または Assets タブから）を選ぶと、メンバーの区画にはシェーダー自身に聞いたプロパティ（`Shader.GetPropertyCount`、`GetPropertyName`、`GetPropertyType`、Range の上下限）が、マテリアルの現在の値とともに並びます。

| プロパティの型 | 操作 |
|---|---|
| Float、Range | 入力欄。Range は上下限を表示 |
| Color | 4 つの入力欄と色見本 |
| Vector | 4 つの入力欄 |
| Texture | テクスチャの名前、サイズ、形式と、Assets タブへの **Go**。ここでは編集不可（テクスチャの差し替えはすでにあり、専用の安全な経路を通ります） |
| Int | 入力欄 |

シェーダーキーワード（`_ALPHATEST_ON` など）はそれぞれトグル付きで並びます。マテリアルを変えると、それを共有するすべての Renderer が変わります。Mod のマテリアル上書きでも同じことが起きるので、区画には共有している Renderer の数が出ます。

保存できるようになる前でも作る価値があるのは、この部分のためです。ここで見つけた色や smoothness の値は、のちの上書きファイルに書くものそのもので、翻訳者のテクスチャ作業も、それを表示しているマテリアルから Go ボタン 1 つの距離になります。

## 安全策

- **開発者ツールの中だけ。** 窓のほかの部分と同じく、スイッチがオンの間だけタブがあります。
- **アップロードなし。** 値の読み書きでテクスチャを作ったり送ったりすることはないので、ここでは Direct3D 12 の心配はありません。テクスチャのプロパティは表示だけで、代入しません。
- **名前は窓の守りを通す。** オブジェクトの名前は何でもありえます。Direct3D 12 では Console と同じく ASCII 以外を `?` で出します。
- **破棄されたオブジェクト。** Unity が破棄した（`== null`）オブジェクトやコンポーネントを選んでいたら、例外ではなく、注記つきで選択を外します。
- **毎フレーム走査しない。** ヒエラルキーは求められたときに組みます。リフレクションのメンバー一覧は型ごとにキャッシュします。Repaint ごとに読むのは選んでいるコンポーネントの値だけです。
- **何も残らない。** ファイルも設定も、起動時の再生もありません。編集で起きる最悪のことは動いているセッションが壊れることで、再起動で直ります。タブを最初に開いたときに一度そう出ます。
- **分離。** リフレクションの失敗、setter の例外、投げるシェーダーの問い合わせは、行ごとに捕まえてその行に出します。

## Console

- `inspect` でヒエラルキーのルートを一覧。`inspect <名前またはパス>` でオブジェクトを選び（パスの区切りは `/`。パスでなければ名前の最初の一致）、タブをそこに開く。`inspect <パス> <コンポーネント>` でコンポーネントを選ぶ。
- `inspect set <パス> <コンポーネント> <メンバー> <値>` で、行と同じ解釈で Console から 1 つの値を入れる。手で打つ用で、スクリプト言語は相変わらずありません。
- 補完は、いまの検索に合うオブジェクト名と、パスのあとにそのコンポーネント名を出します。

## Mod 作者向け

- `ToolWindow.Inspect(UnityEngine.Object target)` で、オブジェクト、コンポーネント、マテリアルを選んでタブを開けます。Mod 自身のタブで、一覧の横に **Inspect** ボタンを置けます。
- 宣言は不要です。Mod 自身のものも含め、すべてのオブジェクトとコンポーネントが出ます。Unity の `[HideInInspector]` 属性が付いたフィールドは隠します。隠したい Mod はそれを使ってください。
- 型ごとの独自の描画（既定の行より気の利いた操作）はこの設計に含めません。必要が出てきたら、ほかと同じく GUID で登録する形になります。

## 順番

1. 検索と選択付きのヒエラルキー、コンポーネントの区画、読み取り専用のメンバーの区画。これだけでも名前を探すのに役立ちます。
2. 既知の型の編集と、行ごとのエラーの規則。
3. マテリアル：シェーダーのプロパティとキーワード、Assets タブの Inspect ボタン、テクスチャのプロパティから Assets タブへの Go。
4. `inspect` コマンドと補完、`ToolWindow.Inspect`。
5. 切り替えの下の非公開メンバー、リストと配列。
6. RuntimeUnityEditor についての FAQ と、求められれば共存の検証。

この設計に含めないもの：編集の保存（Assets ライブラリでの上書きの設計は後で）、メソッドの呼び出し、コンポーネントの追加と削除、プレハブ、ギズモ、REPL。
