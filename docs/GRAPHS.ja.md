# グラフ：ブロックとノードで組み立てる

[English](GRAPHS.md)

> **作ってあり、まだリリースしていません**（2026-09-20）。[API の計画](API_PLAN.ja.md)の第 4 段階です。Graphs ライブラリがグラフのファイルを読み、検査し、実行します（`src/DragNWash.ModFramework.Graphs`）。その土台になる操作の登録簿・イベントの登録簿・コードなし MOD のローダーは中核にあります。まだ無いのは**エディター**です。ページの Graphs タブができるまで、グラフは手で書きます（[エディター](#エディター)）。[作業の順番](#作業の順番)の第 5 段階（最初の書き込み操作）もまだなので、いまのグラフは読むこととログを書くことはできますが、ゲームを変えることはできません。ゲームなしでできた調査は[調査](#調査)にあり、そのために書いた `tools/graphs.py` の検査器とインタープリターは、いまも同じ規則を見ています。決めたことは末尾にあります。

グラフは、コードのない小さな Mod です。「これが起きたら、これをする」。たとえば「シーンが読み込まれたら、1 秒待って、何があるかを見て、ログに 1 行書く」。`mod.json` のあるフォルダーに入れる JSON のファイルで、[オーバーライドの Mod（wiki）](https://github.com/TomXV/dragnwash-modframework/wiki/Overrides)と同じ形です。呼べるのは、ライブラリが登録した[操作](API_PLAN.ja.md)だけで、コンソールの `op` や Bridge が出しているものと同じです。グラフは Bridge のページで、ブロック（Scratch のような）かノードとして作ります。どちらも同じファイルの見え方の違いです。

## 計画ですでに決めたこと

[計画で決めたこと](API_PLAN.ja.md)から：

- **自由なスクリプトはなし。** グラフが呼べるのは登録された操作だけです。名前でメソッドを呼ぶこと、リフレクション、ファイル、自分での通信はできません。グラフにできることは、それが名前を挙げる操作が許すことと、ちょうど同じです。
- **エディターはゲームの外に置きます。** この PC の Bridge が出すページ（[CODE_GRAPH.ja.md](CODE_GRAPH.ja.md)）で、ゲームはグラフを動かすだけです。
- **オーバーライドと同じ形で配ります。** `mod.json` と `graphs/*.json` のフォルダーで、DLL はなく、Mods 画面に出て、そこでオフにできます。オーバーライドとグラフは、その読み込み役を共有します。
- **何と一緒でも安全に動くこと。** フレームごとの時間の予算があり、3 回続けて失敗したグラフは（[`GameEvents`](../src/DragNWash.ModFramework/GameEvents.cs) のハンドラーと同じように）オフになり、Mods 画面は各グラフが使う操作を、動く前に並べます。

## グラフのファイル

```
BepInEx/plugins/<Mod>/mod.json           name、authors、description、version（オーバーライドと同じ）
BepInEx/plugins/<Mod>/graphs/*.json      1 ファイルに 1 つのグラフ
BepInEx/plugins/<Mod>/overrides/*.json   なくてもよい。1 つの Mod が両方を持てます
```

グラフのファイルは 1 つの JSON オブジェクトです：

| キー | | 内容 |
|---|---|---|
| `format` | 必須 | `1`。これより新しい形式のファイルは読まず、フレームワークの更新を促します（Overrides ライブラリと同じです）。 |
| `name`、`description` | 任意 | Mods 画面とエディターのため。ないときはファイル名です。 |
| `variables` | 任意 | グラフの変数と最初の値（文字、数、true／false、null）。ゲームが動いている間だけ残り、保存はされません。 |
| `on` | 必須 | 答えるイベント。**ハンドラー**のリストです。 |
| `layout` | 任意 | エディターが各ブロックやノードを描いた位置：`{ "<id>": [x, y] }`。ゲームは読みません。 |

これ以外のキーは誤りとして扱います。打ち間違いを無視せず、すぐに見つけるためです。

**ハンドラーと文には、すべて `id` があります。** ファイルの中で重なりません（エディターは `h1`、`s12` のような短いものを作ります）。エラー、ライブのログ、Mods 画面、`layout` は、どれも id で文を指すので、ブロックを動かしてもずれません。

### ハンドラー：イベント

`{ "id": "h1", "event": "scene.loaded", "when": <式>, "overlap": "skip", "do": [ 文 ] }`

- `when`（任意）は条件です。真のときだけ実行が始まります。
- `overlap`：このハンドラーの実行が（待っているなどで）まだ続いているうちに、同じイベントがまた来たときの扱いです。`skip`（既定）は新しい方を無視し、`queue` はもう 1 つ実行を始めます。グラフ 1 つにつき、同時に 8 つまでです。

グラフが答えられるイベントは、今のライブラリが起こすものと、Graphs ライブラリ自身の 2 つです：

| イベント | 渡す値 | 起こすもの |
|---|---|---|
| `game.started` | | コア、`GameEvents.OnGameStarted` |
| `scene.loaded` | `scene`、`mode` | コア、`GameEvents.OnSceneLoaded` |
| `scene.unloaded` | `scene` | コア、`GameEvents.OnSceneUnloaded` |
| `dialogue.node.started` | `node` | Dialogue、`GameDialogue.NodeStarted` |
| `dialogue.line.showing` | `line_id`、`speaker`、`text` | Dialogue、`GameDialogue.LineShowing` |
| `dialogue.option.showing` | `line_id`、`text` | Dialogue、`GameDialogue.OptionShowing` |
| `saves.written` | `slot` | Flags and saves、`GameSaves.SaveWritten` |
| `timer.every`（新規） | | Graphs：`seconds`（0.5 以上）ごと、実時間 |
| `key.pressed`（新規） | `key` | Graphs：指定した `key`（`F6` などのキー名） |

`GameEvents.OnQuitting` は外しました。ゲームが終わる間に実行は待てず、そのときグラフが何かをしても誰にも見えないからです。`GameEvents` と同じく、毎フレームのイベントはありません。いちばん速いのは 0.5 秒の `timer.every` です。

実行はイベントの中では始まりません。値を写し取り、Graphs ライブラリの次の `Update` で始めます。これで、グラフがほかのライブラリのフック（台詞を出している途中、シーンを作っている途中）の最中に動くことはなく、遅いグラフがほかの Mod のイベントを遅らせることもありません。その代わり 1 フレーム遅れるので、グラフは台詞が出る*前*にそれを変えることはできません。それはテキストの書き換え（`GameText.AddRewriter`）の役目で、グラフの役目ではありません。

### 文

文は `id` と、次のキーのうちちょうど 1 つを持つオブジェクトです：

| 文 | 書き方 | 内容 |
|---|---|---|
| call | `{"call": "saves.flags.list", "args": {"slot": ...}, "as": "flags", "onError": [...]}` | 操作を呼びます。名前は計算せず書き出すので、グラフが何を呼べるかは動く前にわかります。`args` は式です。`as` は結果を、この実行のあとの文のために取っておきます。`onError` がなければ、失敗した呼び出しは実行を失敗させます。あれば、代わりに `onError` の文が動き、メッセージは `error` に入ります。 |
| set | `{"set": "count", "to": <式>}` | グラフの変数（`variables` に挙げたもの）に値を入れます。 |
| if | `{"if": <式>, "then": [...], "else": [...]}` | |
| wait | `{"wait": 1.5}` | 実時間の秒数（ゲームの一時停止や時間の倍率では伸びません）、0 から 600。`0` は次のフレームです。 |
| repeat | `{"repeat": 5, "do": [...]}` | 決まった回数、1 から 1000。 |
| while | `{"while": <式>, "max": 100, "do": [...]}` | 真の間、最大 `max` 回（1 から 1000、必須）。`max` 回のあとも真なら、実行は失敗します。終わらないループは間違いであって、黙って続けるものではないからです。 |
| each | `{"each": <式>, "as": "item", "max": 50, "do": [...]}` | リスト（たいていは結果）の要素ごとに 1 回。`max` より長いリストは実行を失敗させます。 |
| log | `{"log": <式>, "level": "Info"}` | グラフの Mod の名前でログに 1 行（`Info`、`Warning`、`Error`）。グラフ 1 つにつき 1 秒に 20 行まで。それを超えた分は数えるだけで、書きません。 |
| stop | `{"stop": true}` | この実行を終えます（グラフは終えません）。 |

`goto` も、ほかのハンドラーを動かす文も、再帰もありません。どの実行も必ず終わり、どれだけで終わるかは制限が決めます。

### 式

式は、そのままの値（`"text"`、`3`、`true`、`null`）か、演算子を 1 つ持つオブジェクトです：

| | |
|---|---|
| `{"var": "name"}` | グラフの変数か、その実行で前に `as` で名前をつけた結果（`onError` の中では `error`）。 |
| `{"event": "scene"}` | イベントが渡した値。 |
| `{"get": [<式>, "key", 0, ...]}` | オブジェクトのフィールド、リストの要素（0 が最初、-1 が最後）。ないときは何もなし（null）。 |
| `eq`、`ne`、`lt`、`le`、`gt`、`ge` | `{"gt": [a, b]}`。数どうしは数として、それ以外は文字として比べます。 |
| `add`、`sub`、`mul`、`div` | 数だけ。それ以外や 0 での割り算は、実行を失敗させます。 |
| `and`、`or` | `{"and": [a, b, ...]}` |
| `not` | `{"not": a}` |
| `join` | `{"join": ["Scene ", {"event": "scene"}]}`：文字をつなげます。リストとオブジェクトは JSON として書きます。 |
| `contains` | `{"contains": [a, b]}`：文字の中の文字（大文字小文字は区別しません）、またはリストの中の要素。 |
| `length` | `{"length": a}`：文字、リスト、オブジェクトの長さ。それ以外は 0。 |

値は、操作がすでに返しているものと同じです。null、文字、数、true／false、それらのリストとオブジェクト。false、0、`""`、null、空のリストとオブジェクトは偽として扱います。引数はコンソールと同じく登録簿が変換します（数の引数に `"3"` を渡しても動きます）。

形は JSON Logic に近いです（1 つのオブジェクトに 1 つの演算子、引数はリスト）。人が読みやすく、検査もしやすい形です。

### 版

`format` は 1 です。新しい文、演算子、ハンドラーのキーは新しい形式になります。古いライブラリは、動かせないファイルに出会うと、半分だけ動かすのではなく、Mods 画面でそう伝えます。ゲームが読まないキー（`layout`）や、新しいイベントや操作には、新しい形式はいりません。ないイベントや操作は、ファイルを動いているゲームと照らし合わせたとき（下）に見つかります。

### 例

今の操作にできることは、見ることです。このグラフは、シーンが読み込まれたときにログにメモを書き、子の多いルートについて警告し、ゲームがセーブしたときにそのセーブのフラグを数えます。Inspector の操作を使うので、Inspector が入っている必要があり、Mods 画面はそう出します。

```json
{
  "format": 1,
  "name": "Scene notes",
  "description": "Writes to the log what each scene has at its top level, and how many flags each save holds.",
  "variables": { "scenes": 0 },
  "on": [
    {
      "id": "h1",
      "event": "scene.loaded",
      "do": [
        { "id": "s1", "set": "scenes", "to": { "add": [{ "var": "scenes" }, 1] } },
        { "id": "s2", "wait": 1 },
        { "id": "s3", "call": "inspector.objects.children", "as": "roots" },
        { "id": "s4", "log": { "join": ["Scene ", { "event": "scene" }, " (", { "var": "scenes" }, " this session): ", { "length": { "var": "roots" } }, " root objects"] } },
        { "id": "s5", "each": { "var": "roots" }, "as": "root", "max": 200, "do": [
          { "id": "s6", "if": { "gt": [{ "get": [{ "var": "root" }, "children"] }, 50] }, "then": [
            { "id": "s7", "level": "Warning", "log": { "join": [{ "get": [{ "var": "root" }, "path"] }, " has ", { "get": [{ "var": "root" }, "children"] }, " children"] } }
          ] }
        ] }
      ]
    },
    {
      "id": "h2",
      "event": "saves.written",
      "do": [
        { "id": "s8", "call": "saves.flags.list", "args": { "slot": { "event": "slot" } }, "as": "flags",
          "onError": [{ "id": "s9", "level": "Warning", "log": { "join": ["Could not read ", { "event": "slot" }, ": ", { "var": "error" }] } }] },
        { "id": "s10", "log": { "join": [{ "event": "slot" }, " was saved: ", { "length": { "var": "flags" } }, " flags"] } }
      ]
    }
  ]
}
```

`python tools/graphs.py --test` は、英語版のこの例を `src/` の操作と照らし合わせ、ゲームの代わりのものを使って動かします。例が登録簿からずれることはありません。

ブロックで見ると、ハンドラー `h1` は帽子のブロックの下の 1 つの積み重ねになります：

```
シーンが読み込まれたとき
  scenes を (scenes + 1) にする
  1 秒待つ
  roots = inspector › objects › children
  ログ "Scene " (scene) " (" (scenes) " this session): " (roots の長さ) " root objects"
  roots の root ごとに（最大 200）
    もし (root › children) > 50 なら
      警告のログ (root › path) " has " (root › children) " children"
```

## 足りないもの

今（2026-09-20）の登録簿には **31 の操作があり、30 が読むもの、1 が書くもの**です。ページ専用の 5 つ（ゲームのコードを見せる `code.*`）と、Bridge の `bridge.page.open`（唯一の書く操作）を除くと、**グラフが呼べるのは 25 で、すべて読むもの**です。つまり、グラフにできるのは、見ることとログに書くことだけです。Mod の作り手には役に立ちますが（報告、確認、「これが起きたら教えて」）、プレイヤーにはまだです。

| ライブラリ | グラフが呼べる操作 |
|---|---|
| コア | `mods.list`、`mods.network`、`game.info`、`scene.list` |
| Tool window | `log.read` |
| Assets | `assets.textures.list`、`assets.materials.list`、`assets.meshes.list`、`assets.replacements.list`、`assets.fonts.language` |
| Dialogue | `dialogue.current`、`dialogue.recent` |
| Text | `text.rewriters`、`text.shown` |
| Flags and saves | `saves.list`、`saves.flags.list`、`saves.flags.get` |
| Inspector | `inspector.objects.find`、`inspector.objects.children`、`inspector.components.list`、`inspector.member.get`、`inspector.selection.get` |

### グラフが最初に必要とする書く操作

役に立つ順に、それぞれの取り消し方と一緒に：

| 操作 | 内容 | 取り消し |
|---|---|---|
| `objects.member.set` | コンポーネントのフィールドやプロパティ。オーバーライドの 1 行と同じです（`path`、`component`、`index`、`member`、`private`、文字の `value` を `OverrideValues` で読む）。 | 前の値をグラフごとに取っておきます。オーバーライドの `OverrideApplier.TakeBackAll` と同じです。 |
| `objects.material.set` | マテリアルのプロパティ（`material`、`property` のあるオーバーライドの行）。 | 同じ。 |
| `objects.active.set` | オブジェクトを出す／隠す。 | 前の状態。 |
| `saves.flags.set` | セーブスロットのフラグ 1 つ（`GameSaves.SetFlag`。先にスナップショットを取ります）。 | スナップショット（Saves タブの履歴）。**残る**書き込みです。ファイルを変え、セッションが終わっても残ります。 |

最初の 3 つは、オーバーライドがすでにしていることを、オブジェクトが現れたときではなく、グラフが選んだときにするだけです。`saves.flags.set` は種類が違います。ゲームを閉じても残り、スロットを読み込み直すまで効きません（Saves タブも同じことを言います）。これは後にします（決めたこと 5）。

操作のほかに足りないもの：

- **イベント**：レベルの始まりと終わり、プレイヤーの行動、オブジェクトが現れたこと。どれも、まずゲームのコードの調査がいり（コードのグラフがそのための道具です）、それをフックするライブラリのものになります。
- **プレイヤーへのメッセージ。** 出せるのはログだけです。小さなお知らせ（ロードマップの「Mods 画面の Mod ごとのお知らせ」や、画面の 1 行）には、それだけの設計がいります。
- **Mod 自身の操作。** Drag'n Wash Localization が `loc.line.get` や `loc.coverage`（計画の例）を登録すれば、ここを何も変えずにグラフから使えます。

### 書き込みを安全に保つには

1. **種類。** どの操作も*読む*か*書く*かを言います。これに 3 つ目の印、**残る**（セッションより長く残る書き込み：ファイル、セーブ）を足し、Mods 画面が「ゲームの値を変える」より強い言葉で「セーブを変える」と言えるようにします。最初の版では、グラフは残る書き込みを呼べません。
2. **取り消し。** 書く操作は、取り消し方を登録簿に渡します。新しい `OperationArgs.TakeBack(label, undo)` を通してです。Graphs ライブラリはそれをグラフごとに持ち、グラフがオフになったとき、読み込み直されたとき、3 回目に失敗したときに、新しい順に実行します。取り消せない書き込みは、グラフには出しません。
3. **履歴。** 登録簿は `Operations.Written`（操作、呼び出し元、ラベル、前、後）を起こします。Inspector が入っていれば、それを呼び出し元（`graph:<mod>/<file>`）と一緒に History に並べ、人がそこで 1 つずつ見て取り消せます。Inspector の History は今は内部のものですが、これは小さなフックで、移し替えではありません。
4. **動く前に。** Mods 画面が、各グラフが使うものを、書くものを先にして並べます（下）。
5. **ログ。** 登録簿が今しているとおり、書き込みはすべて呼び出し元と一緒に Info で記録します。

## 実行：Graphs ライブラリ

新しいライブラリ **Graphs**（`DragNWash.ModFramework.Graphs`、`com.tomxv.dragnwash.modframework.graphs`）。独立したプラグインで、コアに依存します。グラフのファイルを読み、検査し、動かし、一覧にします。個々の操作のことは何も知らず、すべて `Operations` を通します。

### 検査は一度、読み込むときに

ファイルは、何かが動く前に、*今*登録されている操作と照らし合わせて丸ごと検査します（すべてのプラグインの `Awake` のあと、`ModFramework.Ready` で）：

- 形：上のキー、id、文、式。文は 2,000 まで、入れ子は 32 段まで、ファイルは 256 KB まで（Overrides ライブラリは値を 2 MB まで読みますが、グラフはもっと小さいものです）。
- どの `call` も、存在し、ページ専用でなく、グラフに出している操作を指していること。必須の引数がそろっていること。書き出した引数の型が合い、許された選択肢の 1 つであること。
- どの `{"var"}` もグラフの変数か前の `as` の名前であること。どの `{"event"}` もそのイベントが渡す値であること。

問題のあるファイルはまったく動かず、問題はオーバーライドと同じく Mods 画面に並びます。入っていないライブラリの操作を使うグラフは、あとで失敗するのではなく、*Inspector が必要* と出します。

### 動かす

- **実行**は、位置（文のリスト、何番目か、ループの状態）の小さなスタックで、スレッドでもコルーチンでもありません。実行の状態はすべてデータなので、どの文でも止め、一覧にし、終わらせられます。
- **フレームごとの時間の予算**：すべてのグラフを合わせて、1 フレームに **1 ms**（`[Graphs] FrameBudgetMs`）。実行の間で順番に分け、時計は 16 ステップごとに読みます。予算を使い切ったら、次のフレームに続けます。操作の呼び出しは途中で切れないので、5 ms より長くかかった呼び出しは、遅い `GameEvents` のハンドラーと同じく、グラフの名前と一緒に Debug で記録します。
- **実行ごとの制限**：10,000 ステップ。ループはそれぞれ 1,000 回まで（`max` は必須）。待つのは 600 秒まで。グラフ 1 つにつき、同時に動く実行は 8 つまで。
- **失敗**：（`onError` なしで）呼び出しが失敗したとき、制限に達したとき、型の誤り。実行は終わり、エラーはグラフ、ファイル、文の id と一緒に記録され、数に入ります。普通に終わった実行は数を 0 に戻します。
- **3 回続けて失敗したグラフは、そのセッションの間オフ**になり、書き込みは取り消され、`GameHooks.Unavailable` で Mods 画面に印がつきます（`GameEvents` のハンドラーと同じです）。同じ Mod のほかのグラフは動き続けます。
- **持ち主**：呼び出しはすべて `graph:<Mod の GUID>/<ファイル>` として行います（登録簿は呼び出し元を記録します）。ライブラリが読み込み直されたり外されたりすると（`ModReload.Unloading`）、その操作はなくなります。それを使うグラフは、失敗に数えずに止まり、操作が戻ればまた始まります。
- **読み込み直し**：コンソールの `graphs reload` か、ページからの保存で、ファイル 1 つかすべてを読み込み直します。実行を止め、書き込みを取り消し、変数を最初に戻し、ファイルをもう一度検査して、始めます。何も持ち越さないので、読み込み直しは新しく始めるのと同じになります。

### データの Mod、読み込み役は 1 つ

今は Overrides ライブラリが自分で Mod を探し（`OverrideFiles.Scan`：`mod.json` と `overrides/` のあるフォルダー）、それぞれを `ModFramework.RegisterDataMod` で並べ、オフにすると次の起動で `mod.json` が `mod.json.disabled` になります。`overrides/` と `graphs/` の両方があるフォルダーは、Mods 画面で **1 つ**の Mod であり、一度でオフになるべきです。

やり方は 2 つです（決めたこと 3）：

- **A. コアが `mod.json` を読む。** コアの小さな `DataMods`（すでにある `RegisterDataMod` の隣）が `mod.json` のあるフォルダーを探し、マニフェストを一度読み、Mod を並べます。Overrides と Graphs は、自分のサブフォルダーのあるフォルダーをそこに尋ね、Mod の詳細に 1 行足します（*値 12 個*、*グラフ 2 つ*）。どちらのライブラリも、もう一方に依存しません。
- **B. Graphs が Overrides に依存する。** Overrides がデータの Mod の読み込み役になり、`graphs/` のあるフォルダーを Graphs に渡します。コアは変わりませんが、グラフだけの Mod にも Overrides ライブラリがいることになります。

### オフにすること、Mods 画面

- **Mod** は、ほかのデータの Mod と同じくオフにします。次の起動で `mod.json.disabled` になります。
- Mod の詳細の **グラフのページ**（`ModFramework.AddModsPage`）が、グラフごとに、そのイベント、使うもの、動いているか、失敗の数、そして **このセッションだけ止める** ボタン（書き込みは取り消し）を並べます。グラフごとに残るスイッチはありません。グラフを選べるようにしたい Mod は、2 つの Mod に分けて配ります。

### Mod どうしが出会うとき

- **2 つのグラフが同じもの**（同じオブジェクトとメンバー）**に書く**：両方の書き込みが行われ、あとのものが勝ち、Mods 画面は両方の Mod について一度だけ書きます（*Scene tweaks と Night mode の両方が Sun [Light] intensity を変えます*）。今のオーバーライド（`SaidConflict`）と同じです。片方のグラフを止めると、その取り消しは*それが*見つけた値に戻しますが、それはもう一方のグラフの値かもしれません。そこで取り消しは新しい順に行い、自分が書いたのではない値を見つけた取り消しは、それを触らずに記録します。
- **オーバーライドの行とグラフ**が同じメンバーに：同じ決まりです。Overrides ライブラリはオブジェクトが現れたときに、グラフは動いたときに書きます。
- 2 つのグラフの **同じキー**（`key.pressed`）：両方動きます。グラフのページが、そのキーを聞いている Mod を示します。フレームワークが使うキー（F1）は、読み込むときに断ります。
- **名前**：グラフには、ほかから呼べる名前がないので、ぶつかるものはありません。変数はそのグラフのものです。

## エディター

Bridge のページの、コードのグラフの隣に **Graphs** のタブを置きます。開き方は同じです（F1 の窓のボタン、Windows の Code Graph アプリ、一度きりの合言葉と Cookie）。ページもサインインも 1 つのままです。

- **ブロック**（Scratch のような）：ハンドラーは帽子のブロックで、その下に積み重ねがあります。`if`、`repeat`、`while`、`each`、`onError` は C の形のブロック、式は枠にはめる丸いブロックです。操作は登録簿から、ライブラリごとにまとめて出し、引数を枠に（選択肢はリスト、true／false はチェック）、説明をツールチップに、種類を色に（書くものは目立つように）します。
- **ノード**：同じ文を箱にします。流れは辺を下ります（*then*、*else*、*要素ごと*、*次*）。`as` で名前をつけた結果は、呼び出しから使う場所への線です。ファイルは木なので、ノードの見え方も木のままです。流れの出口の線は 1 本で、ループは戻る線ではなくループのノードです。ブロックで書けないものはノードでも描けないので、見え方を切り替えても何も失いません。
- **1 つのファイル、2 つの見え方。** どちらも同じ JSON を編集します。`layout` がブロックとノードを描いた位置を（id ごとに）持ちます。ページは編集しながら検査し（ゲームと同じ決まりで、ページが一覧にした操作と照らし合わせて）、問題をブロックの上に出します。
- コードのグラフと同じく、ページ自身のコードで描きます。インターネットから何も取らず、ライブラリも同梱しません（決めたこと 6）。

### ページが Bridge に求めるもの

ページは自分の扉（`POST /page/api/op`）で操作を呼ぶので、Graphs ライブラリが次を登録します。どれも **ページ専用**（MCP には出しません）です：

| 操作 | 種類 | 内容 |
|---|---|---|
| `graphs.catalog` | 読む | グラフが呼べるすべての操作と、その引数（型、必須か、選択肢、説明）、返すもの、種類。それとイベントと、その値。 |
| `graphs.list` | 読む | 読み込まれたグラフの Mod とグラフ：状態、失敗、使うもの。 |
| `graphs.read` | 読む | グラフのファイル 1 つの中身。 |
| `graphs.check` | 読む | 文字で渡されたグラフを検査します。問題を文の id ごとに。 |
| `graphs.save` | 書く | データの Mod の `graphs/` にグラフを書き（新しい Mod ならフォルダーと `mod.json` も作り）、読み込み直します。 |
| `graphs.run` | 書く | ハンドラー 1 つを、ページが渡した値で今すぐ始めます（イベントを待たずに試すため）。 |
| `graphs.stop` | 書く | グラフをこのセッションだけ止め、書き込みを取り消します。 |
| `graphs.log` | 読む | ログのグラフの行のうち、指定した番号より後のもの。ページのライブのログのため（0.5 秒ごとに問い合わせます。Bridge には server-sent events がありません）。 |

Bridge で変わることが 2 つあります：

- **ページの扉は、今は書く操作を断ります**（`PageDoor.Call`：*No read operation named …*）。これを、**ページ専用**の書く操作だけは受け付けるようにします。ページはグラフを保存して動かせますが、`objects.member.set` を自分で呼ぶことはできません。MCP は読むだけのままで、`graphs.*` は見えません（決めたこと 2）。
- **保存できる場所**：`BepInEx/plugins/<フォルダー>/graphs/<名前>.json` だけです。フォルダーはデータの Mod（`mod.json` があり DLL がない）か新しいもので、`<名前>` は英数字と `-`、`_`、中身は 256 KB までで `graphs.check` を通るもの。ほかの場所には書かず、DLL の Mod のフォルダーを上書きせず、前のファイルを `<名前>.json.bak` として残します。

## 安全とプレイヤーからの見え方

グラフに**できない**こと（作りからしてできないこと）：名前でメソッドを呼ぶこと、リフレクション、ファイルを読み書きすること、接続を開くこと、プログラムを起動すること、ページ専用の操作（ゲームのコード）を呼ぶこと、Bridge の操作を呼ぶこと、いつまでも動くこと、フレームの持ち分より多くを使うこと。グラフが触れるのは、登録された操作がすることだけで、グラフが新しく足すのは「いつ」だけです。

プレイヤーが**動く前に**見るもの。[通信する Mod（wiki）](https://github.com/TomXV/dragnwash-modframework/wiki/Going-online)と同じ考え方で、グラフの Mod の Mods 画面の詳細に、グラフごとに次を出します：

```
Scene notes (graphs/scene-notes.json)
  答えるもの: シーンの読み込み、セーブの書き込み
  読むもの:   inspector.objects.children、saves.flags.list
  変えるもの: なし
  必要なもの: Inspector
```

書くものがあれば先に、注意の色で並べます（*変えるもの: objects.member.set — ゲームのオブジェクトの値を変えます。オフにすると取り消します*）。オーバーライドと同じく、private のメンバーについての 1 行（*ゲームのスクリプトの private の値を変えます*）も出します。`private` の引数が書き出されていればそこから取り、計算されていれば、変えるものとみなします。

- **通信**：今、通信する操作はありません。いつかできれば、そのライブラリが `ModInfo.Network` で宣言し、それを呼ぶグラフはここに *<操作> を通して通信します* と出します。
- **同意**：確認を求めるのではなく、知らせます。オーバーライド（尋ねずに値を変えます）や通信と同じです。書き込みは Mod をオフにすると取り消されます（決めたこと 4）。
- **コンテンツの方針**：グラフは作った人自身のものです。グラフが持つのはオブジェクト、メンバー、操作の名前で、ゲームのテキストやコードではありません。台詞をログに書くグラフも、書く先はプレイヤー自身のログだけです。[CONTENT_POLICY.ja.md](CONTENT_POLICY.ja.md) を見てください。

### ほかのエディターのファイルの持ち方

一般に知られていることからです（この記録のために改めて文書を読んではいないので、細かいところは古いかもしれません）：

- **Scratch** は、スプライトごとのブロックを、ブロックの id を鍵にした 1 つの平らな表に持ちます。ブロックは `next` と `parent` を名前で持ち、入力は id でほかのブロックを指し、いちばん上のブロックが `x`、`y` を持ちます。
- **Blockly** は JSON を木として保存します。ブロックがフィールドを持ち、入力が中のブロックを持ち、`next` が下のブロックを持ちます。いちばん上のブロックが `x`、`y` を持ちます。
- **Node-RED** はノードの平らなリストを持ちます。それぞれに `id`、種類、`x`、`y`、`wires`（出口ごとに、つながる id）があります。流れは自由なグラフで、線でループを作ることもできます。

この設計は、Blockly のような木に、Scratch のような id をつけ、位置を別に（`layout`）持ちます。木なら制限を検査しやすく（ループはどれも `max` のあるループの文で、戻る線はありません）、テキストエディターでも差分でも読みやすく、2 つの見え方の両方に合うからです。手放すのは Node-RED の自由な配線だけです。2 か所へ同時に値を送るノードや、線で描くループはできません。

### 1 ステップの重さ

同じ形のツリーインタープリターを、小さな C# のベンチマーク（リポジトリには残していません）で動かしました。文は JSON から一度だけオブジェクトに組み立て、値はボックス化し、変数はスロットに置き、操作の呼び出しは登録簿の手順を写したもの（引数を辞書に入れ、変換し、関数を動かし、サイズの上限のために結果を JSON にし、ログの行を作る）を通します。この PC（Windows 11）の .NET Framework 4.8 と .NET 9 で：

| 同じもの、毎ステップ時計を読む | 26 ns | 26 ns |
| 4 つをつなぐ `join` | 256 ns | 168 ns |

## 決めたこと

2026-09-20 にオーナーが決めました。

1. **グラフが呼べる操作は、操作ごとに「誰向けか」を持たせます。** `PageOnly` を「誰向けか」（console / page / MCP / graphs）に広げ、人には出すがグラフには出さない、という指定ができるようにします。`bridge.*` と `code.*` はグラフ向けにしません。
2. **ページからの書き込みは、ページ専用の扉だけを通します。MCP は通しません。** グラフの保存と実行に要るページ専用の書き込みは扉が受け、MCP は読み取り専用のままです。AI クライアントにグラフを書かせるかどうかは、別に決めることで、ここでは決めません。
3. **コードなし Mod の読み込み口は、コアに 1 つ置きます。** コアにはすでに `RegisterDataMod` と `mod.json.disabled` の切り替えがあります。グラフだけの Mod に Overrides ライブラリは要らず、どちらのライブラリも相手に依存しません。
4. **書き込むグラフは、Mods 画面で告知します。** overrides や通信と同じ扱いです。Mod をオフにすれば書き込みは戻るので、実行前の問い合わせは出しません。
5. **セーブに残る書き込みは、最初の版には入れません。** 入れるときは、それを使うグラフを警告の色で示し、Saves タブのスナップショットを戻し手段にします。
6. **エディターは自前で描きます。** コードグラフと同じやり方です。Blockly は Bridge の中に抱えるには大きく、ここでのブロックは少数です（文 9 個、演算子 19 個）。
7. **オブジェクトへの書き込みは Overrides ライブラリに置き**、名前は `objects.*` にします。値の解釈、パスからオブジェクトを探すこと、元に戻すことが、すでにそこにあります。グラフの Mod を入れる遊ぶ人は Overrides を持っていますが、Inspector（Mod を作る人の道具）は持っていません。Inspector の History は `Operations.Written` でつながります。
8. **イベントは、最初の版から、それを出すライブラリのものにします。** 操作の隣に小さなイベントの登録を置き（`Operations.RegisterEvent`、出すのは各ライブラリ）、Graphs ライブラリに直書きした表と置き換えます。会話のイベントは Dialogue、セーブのものは Flags and saves、`timer.every` と `key.pressed` は Graphs が持ち、Mod も自分のイベントを足せます。上の表のイベントはそのままで、Graphs に並べる代わりに、それぞれのライブラリが登録します。
