# 台詞の安定したキー

[English](STABLE_LINE_KEYS.md)

> **実験的な機能です。** `experimental/stable-line-keys` ブランチの Dialogue ライブラリ 1.1.0 から入っています。リリースまでに定義が変わることがあります。

台詞について何かを覚えておく Mod（翻訳、しおり、チャプターの目印）は、ゲームの更新のあとで同じ台詞を見つけ直す必要があります。英文そのものをキーにすると、わずかな修正で壊れます。2026 年 9 月 14 日の更新では 24 行の誤字が直され、その全部の翻訳が英語に戻りました。Yarn の台詞 ID だけをキーにすると、開発元が ID を振り直したときや台詞を作り直したときに壊れます。このライブラリは 4 種類のキーを持ち、強い順に試します。

## キー

どれも Dialogue ライブラリの `LineKey` が計算し、`tools/linekeys.py` にも同じ定義があります。どのキーにも本文は含まれないので、キーをリポジトリに入れてもゲームの台本は配布されません。

| キー | 定義 | 耐えられる変化 |
|---|---|---|
| 台詞 ID | Yarn の `line:xxxxxxxx` タグ。`DialogueLine.LineId` の値 | 本文のどんな修正にも |
| ハッシュ | コンポーネントが受け取った UTF-8 の本文（タグ込み）の SHA-256 の先頭 16 桁 | なし。今の翻訳パックのキー |
| 正規化ハッシュ | 正規化した本文のハッシュ。`<タグ>` を外し、ASCII の英字を小文字にし、英数字と空白以外を落とし、連続する空白を 1 つにする | 記号、大文字小文字、空白、TextMeshPro のタグの修正 |
| 指紋 | 正規化した本文の 64 ビット SimHash。3 文字ずつの窓を FNV-1a 64 でハッシュし、ビットごとに投票する | 小さな修正。似た本文は数ビットしか離れない（`LineKey.Distance`） |

Yarn の台詞 ID は、コンパイラが台本ファイルに一度だけ書き込むタグです。開発元が本文を直しても残ります。変わるのは、台詞を作り直したときや、台本のタグを振り直したときだけです。

## 台詞の解決

`LineResolver` は Mod の記録（`LineRecord`：上のキー、台詞を見たノードと話者、任意のペイロード）を持ち、`Resolve(line, displayedText)` に答えます。

1. **台詞 ID。** ID が一致する記録があれば、それを採ります。記録のハッシュが画面の本文と違えば `NeedsReview` を立てます。本文が変わったので、Mod のデータが古いかもしれません。
2. **ハッシュ。** 表示される本文そのもの。
3. **正規化ハッシュ。** 一致する記録が 1 つだけのとき。「Yes.」のように複数の台詞が共有する本文は、推測しません。
4. **あいまい照合。** 同じノードの記録の中で（ノードが不明なら全記録、ノードに記録がなければ照合しない）、指紋が一番近いものを採ります。条件は、10 ビット以内、その近さのものが 1 つだけ（同点は話者で絞り、それでも決まらなければ拒否）、両方とも正規化後 12 文字以上。`NeedsReview` を立てます。

それ以外は null です。間違った台詞を出すより、何も出さないほうを選びます。

## 数字の根拠

ゲームの 1,839 行の台詞について、ゲーム自身のデータをローカルで使って測りました（リポジトリには結果だけを置きます）。

- 9 月 14 日の更新をまたいで、消えた台詞 ID は 0 件、ID は同じで本文が変わった台詞は 24 件でした。1 段階目だけで 24 件すべての翻訳が保てた計算です。
- ランダムな 300 行に 3 種類の修正（1 文字の誤字、記号、大文字小文字）を加えたところ、3 段階目と 4 段階目で 68% / 93% / 91% を復元できました。残りは、短すぎるか曖昧として拒否しました。**別の台詞に誤って当てた例は 0 件でした。**

## Mod 作者向け

```csharp
var resolver = new LineResolver();
// データファイルから：ツールが書いたキーと、その台詞について覚えておくもの。
resolver.Add(new LineRecord { LineId = "line:6046bedf", Hash = "84f325bca745e504", NormalizedHash = "…", Fingerprint = 0x…, NormalizedLength = 10, Node = "Ryan_1_intro", Speaker = "Ryan", Payload = "素晴らしい！" });

GameDialogue.LineShowing += line =>
{
    LineMatch match = resolver.Resolve(line, line.FullText);
    if (match != null)
    {
        Use((string)match.Record.Payload);
        if (match.NeedsReview) Log($"{line.LineId}: 本文が変わっています。翻訳を確認してください");
    }
};
```

画面で見た本文から記録を作るには `LineResolver.RecordFor(text, lineId, node, speaker, payload)` を使います。すべてのキーを計算します。ゲームの外では `python tools/linekeys.py "本文"` が同じキーを出し、`python tools/linekeys.py --check` が Python を `ci/linekey-vectors.json` と照合します。C# 側も同じベクターで確認しています。

## これから

- Localization のパックに、今の `key` の隣に、台詞 ID・正規化ハッシュ・指紋の列をツールが書き足します。翻訳者が触る列は変わらず、古いパックもそのまま動きます。
- `rekey` ツールが、ゲームの更新のあとでパックに同じ 4 段階を回し、動いたキーを書き換え、人が見るべき行を一覧にします。
